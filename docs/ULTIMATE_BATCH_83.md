## Concrete production-source bug: ACK for data not yet put on wire

The shared `server/coop/game_link.h::GameLinkPeer` is compiled by both real Yharnam Together client (`emulator/src/core/bloodborne_game_link.h`) and shadNet. Before B83, `Receive` did `unacked.erase(unacked.begin(), unacked.lower_bound(frame.ack))` for any received peer-instance-matching cumulative ACK. If ACK exceeded the sequence number of anything the sender could actually have sent, it cleared all previously unacknowledged reliable packets (including world head/join control), and these packets were never resent. The malformed ACK need not indicate an authenticated attacker: a stale link state, mismatched client/server implementation or corrupt decoded control is enough to warrant fail-closed ACK behavior. No live reproduction is claimed; this is an actual source defect and deterministic protocol invariant.

B83 tracks `sent_reliable_end`, the exclusive sequence upper bound of **fresh reliable packets actually emitted on Flush**. Queued but not flushed packets have a sequence and count in `next_reliable`/Unacked, but no receiver could have seen them. `Receive` retires `unacked` only when `frame.peer_instance == instance && frame.ack <= sent_reliable_end`. A future ACK is ignored, but inbound reliable/unreliable data still processes normally. `RestartStreams` resets `sent_reliable_end` with the sequence stream, avoiding validation against an old game's progress. ACK zero, legitimate ACKs, resends, backoff, 2/3/5-client synthetic streams and the exact B82 lazy resend set are unchanged. This is NOT an authenticated savedata acknowledgement; it is strictly a volatile *network packet* acknowledgment.

Regression: host actually sends reliable seq0 (its ACK lost), queues seq1 but does not Flush, then receives impossible ACK2 and ACK0xFFFFFFFF. Old code deleted seq0 and broke reliability; new code keeps seq0 and unsent seq1. Legitimate ACK1 retires seq0; seq1 is then flushed, delivered and ACKed. Another test ensures malformed future ACK with an inbound reliable packet does not suppress that inbound data. Native production C++20 test runs GCC, Clang, Windows MSVC; genuine emulator GameLink GoogleTests compile and execute on Linux. No game/save/server launch required.
