# Ultimate B43: real selected-server online count and in-game Players browser

**2026-11-10**. Stacked on [Draft B42 PR #98](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/pull/98). User requirement [#100](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/issues/100): chat player roster, online count and server-sourced boss/world announcements. This batch implements **server-side co-op lobby count and an in-game roster screen**, not the boss feed yet.

## What has been found and implemented
1. The authoritative `TeamLobby::players` map represents signed-in **co-op lobby members** on one selected ShadNet shard. `TeamLobby::StateFor` already sends a deliberately bounded `players` list for hosted servers; `bbport/gpu/bbcoop.h` stores only up to **16 non-teammates** and **5 team members**. The on-screen lobby itself shows only a few rows. Therefore `player_count` and `players_size()` are categorically **not** the number of users on that server.
2. Additive protobuf fields `LobbyState.online_count=16` and `LobbyState.online_count_known=17` carry a server-owned count. The count is taken from `players.size()`, not the truncated response nor a guest report. A server without these fields leaves count **unknown**, not zero. This counts **signed-in co-op lobby players**, not unauthenticated raw UDP peers, people on another shard, or a whole federated global region. For all Link peers regardless of lobby readiness, the separate parallel [Draft PR #91](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/pull/91) adds `link_members` to the local host `/status`; these two metrics must be labelled and reconciled rather than summing/double counting.
3. The actual `bbcoop_lobby_view()` C ABI now transfers the count/known flag to `bbport_overlay.cpp`. A **Players (N)** button appears in the in-game/title team UI; mouse, pad and keyboard use the overlay's existing `Button`/focus paths. Opens a dedicated page with filter, paging, status, team distinction, invite, search whole server (through existing authenticated player search), Friends and Close; restore main UI on Exit. It renders from the **bounded authenticated player roster** and clearly displays `Visible from server snapshot: X / N` if the selected server holds more players. No disclosure of raw online ids/IP outside the existing lobby rules; no credentials. Results may omit users not sent to this player; it does not claim to show all.
4. `server/tests/test_team_lobby.cpp` verifies 23 real lobby users on a hosted server with a **two-player** public list limit; the badge remains 23, temporary quiet does not invent a disconnect, true sign-outs reduce count, and team creation does not change total.

## Boss victory announcements: grounded next protocol step, not spoofable free text
Existing map-screen victory source `emulator/src/core/bloodborne_map.cpp::AreaBossFlags` maps 15 area records to boss **defeat progression flags**, and the game currently marks an area clear only if all listed flags are set. `emulator/src/core/bloodborne_party.cpp::MapFlagBase` computes a packed map's 10,000 flag block, while `server/coop/world_log.cpp::WorldLogHost::MapState` accepts changes from an authorized host. `WorldLogKind::MapFlagOn` represents a **delta** in that authoritative host map state; `MapStateMap` and full-snapshot `MapFlagOn` entries at map changes/rejoins **must not** be announced as new boss victories. A raw kill event or boss-fog-enter flag is also not a victory. A broadcast needs carefully audited defeat-flag mapping, server-owned idempotent transition, team-only privacy first, opt-in global feed, localization, DLC/chalice names, no disclosure of hidden player identity and regression for world restore, wipe, rollback and host migration. This is tracked in #100; **no boss notification transport or client feed implemented in B43**.
