# Seamless Hunt Ultimate — playable track contract

Scope decision, 2026-11-15. This is a release and integration contract, not an implementation, deployment or claim of completed testing.

## Fixed decisions

- Extend the current Yharnam Together + bbport client, launcher and server. Retain the existing seamlesshunt.com service, player entry point and backend continuity. Server improvements are in-place upgrades after compatibility and rollback validation, not a move to another community's service. No production changes in this branch.
- The EBOOT-free runtime is paused for this track. Do not block playable improvements on it. Do not describe the current runtime as EBOOT-free.
- Preserve functions and existing settings when simplifying or replacing code. A rewrite must demonstrate correctness and a measurable resource or usability win on the same workload. Compare against a pinned upstream build and record both regressions and wins.
- Keep existing issues and Drive handoffs as evidence and backlog; this document is a routing index, not a replacement. New work records owner, branch, pinned SHA, donor/licence, test scope, and release status. Keep raw chats, saves, game files and credentials private.

## Website data path

Client observations and server-authoritative facts have separate provenance. Prefer facts already accepted by the server for counts, achievements and competitive records. Unknown, stale or unsupported is distinct from zero. Deduplicate by authoritative event identity; restoration, retry, reconnect and boss rematch must not count as new campaign wins. Anonymous aggregates by default; named profiles or public activity require sharing controls. No raw packets, chat, saves, credentials or IP addresses in public telemetry.

Use a bounded asynchronous queue and an aggregated read model; a slow database or website must not stall matchmaking or game traffic. Define freshness, duplicate behavior, retention, queue-full behavior and version compatibility before rollout. Public website requests should not query hot game state directly. Proposed additions require comparison with existing website feeds before implementing a second collector. 3D map is not a prerequisite for statistics or location lists.

Bloodborne gates: party persists across lamps, zone/Dream/Chalice transitions, boss victories, player deaths and full wipes; correct spectator/respawn transitions; reconnect, host departure and safe exit; eligible earned rewards and optional additive Shared Progress without overwriting personal flags. - **Voice (#96):** independent opt-in proximity and team voice; distance and map scoping; mute/block, volume, PTT and microphone controls. No cross-map, hidden hostile or unrelated-session disclosure. - **Text (#95, #103; drafts #98 and #102):** independently enabled team/session and global server channels. - **Quit to Desktop (#78):** visible separate action in the original title/main menu, not just L3+R3, the overlay, System or Leave Team. Reuse a verified graceful exit path where applicable. ## Relationship, social and input requirements — clarification

These extend the playable backlog without changing the existing SeamlessHunt.com service or restarting the no-EBOOT track. They are requirements and proposed implementation boundaries, not shipped code.

- **Relationship scope:** aim for authored interactions with every NPC and boss, not ordinary enemies. Keep vanilla NPC dialogue, quests and rewards separate. Add optional dialogue, fitting gifts accepted per character, affinity milestones and fitting rewards from the existing item pool. Romance is an optional branch for eligible characters; do not require it for affinity, force a pairing, or invent a final eligibility table. Consider covenant offerings/rewards if they add a distinct purpose; otherwise use the same relationship system rather than duplicating progression.
- **Boss mercy:** when the fight permits a scripted resolution, offer kill versus spare. A spared boss can become a non-hostile NPC with dialogue, gifts, affinity and an appropriate romance route where authored. Store mercy separately from kill and first-clear events. Specify exit/fog/lamp/next-area and required reward handling per boss; mercy must not strand the campaign, silently trigger vanilla death-dependent quests, create duplicate rewards, or publish a kill. Pilot Gascoigne: after a successful mercy resolution, investigate a later visit near his home with dialogue for him and/or his daughter, consistent with the family's quest state. The home scene is a future branch, not a verified available NPC behavior. Use existing animations, optional nonverbal sounds and new text/subtitles instead of requiring new voice acting. Do not bundle game assets.
- **Persistence and co-op:** use per-character, per-NG relationship state and explicit reward receipts. Do not import a host's affinity or romance choices into a guest's personal save. Define encounter authority, save/reload behavior, late join, disable/rollback and compatibility before enabling in multiplayer. Start with a disposable-save solo pilot, then test campaign progression and co-op separately. Bloodborne Enhanced and #116 are references for optional rematches and event isolation, not evidence of a ready mercy/relationship system.
- **Personal in-game communications controls (#95, #96, #103):** voice and text each have their own always-accessible enable/disable switch. Global, team and friend DM are distinct text scopes; proximity and team voice are distinct. Host/server policy may restrict availability but cannot enable a player's mic or override local mute/disable. No voice capture/transmit or playback when locally disabled. From Friends, select an online friend, send a DM and reply in game regardless of whether they are in the same party, within supported service scope. Enforce authenticated recipient, block/mute and rate limits; do not expose DMs to team/global or assume offline storage.
- **Friend presence (#100, #103, #119):** show permitted location, BL, build and current activity (hosting, joined, boss fight, spectating, invading, etc.) in the in-game Friends list. Reuse validated activity/build semantics where possible, with friend-only field sharing, stale/offline/unknown states and no disclosure of hidden invaders, private room/join data or unshared build details. Do not make private presence public website telemetry.
- **Dedicated jump (#244):** standalone rebindable action, including L3 and Xbox B / PlayStation Circle as choices, with original behavior selectable. Jump must not trigger dodge/sprint or steal L3 lock-on silently. Resolve conflicting bindings explicitly and test controller/keyboard, menu navigation, prompts, save/reload of bindings and gameplay gates.

## In-game settings, Dream services, completion and presence

- **In-game settings (related #87, but not launcher-only):** unify discoverability of vanilla System options and runtime/launcher-added options under a coherent tabbed in-game UX. Suggested tabs: Gameplay, Controls, Graphics/Display, Audio/Voice, Online/Social, Accessibility, Mods/Offline, Advanced. Avoid duplicate competing settings, distinguish live versus restart-required and local versus server-controlled, retain all existing options, and support mouse, keyboard and controller. Keep FOV and supported skip options explicit, individually reversible and tested; never skip progression-critical scenes or change co-op synchronization silently.
- **Dream services and encounters (#116, B137):** optional Boss Rush separate from campaign state, rematches of defeated bosses, and manual NG+ after a qualifying ending (including Gehrman or Moon Presence routes, without cutting off the latter). Respec at the Doll or a statue with preview, original class minimums, no net stat/level gain and rollback-safe save. Mirror opens the same full appearance editor as character creation, not a reduced preset dialog or a new hunter; retain stats, inventory, quests and character identity. Stress face edits, previews, repeated open/save/reload and different GPUs for vertex/cache corruption, stale resources and memory growth (#25). Do not claim all vertex explosions share a cause.
- **Offline legacy tools:** inspect and restore compatible legacy YT cheat-menu options offline. Hide and disable them on transition to online, enforce at the action layer rather than hiding only the UI. Clear temporary effects; if persistent edits cannot be distinguished or reverted safely, isolate cheat profiles from normal online play. Verify connect/reconnect and failure paths.
- **Travel to teammate:** add a direct Travel action from the permitted teammate list, not merely travel to their nearest lamp. Server validates both participants, destination and session; choose a safe spawn near the target, recheck on arrival and reject or fall back visibly if loading, combat, inaccessible progression, PvP or an unsafe destination would break the session. Do not disclose hidden players or silently unlock progression.
- **Completion journal:** standalone in-game UI first, optional map layer later; no dependency on the deferred website map. Per-area and per-category 0–100% with counts and acquired/completed marks, covering bosses, NPCs/quests, locations/lamps, pickups, outfits, weapons, Blood Gems and Caryll Runes, base game, DLC and applicable Chalice content. Track unique fixed discoveries separately from random/repeatable items and mutually exclusive quest outcomes, define denominators and character/NG scope, distinguish inventory now from ever obtained, and do not count host flags as guest completion. Unverified/unknown remains unknown; spoiler filters for undiscovered entries. Keep catalog and save-state indexing off the frame hot path.
- **Discord Rich Presence (#119/#103):** exact app title `BBSC: Yharnam Together`, location beneath it, then `BL 25     STR Build` (BL, not PL; nearby on the same row, not opposite edges). For single stats use Strength/Skill/Arcane/Bloodtinge Build where space allows; STR+SKL is Quality Build; other hybrids use ordered slash labels such as STR/SKL/ARC, using the existing >=18 threshold. Activity: Hosting (2/5), In co-op (2/5), Spectating (2/5), Invading, and Fighting <boss>. Preserve role and actual group size while spectating, subject to privacy. Desired game-session elapsed time and encounter elapsed time are separate internally. Discord's standard details/state and activity timestamps do not guarantee arbitrary extra rows or two simultaneous live timers; prioritize location and the compact BL/build pair, use available party metadata/tooltips and show the full state and both clocks in game if needed. Validate actual Discord clients before claiming layout parity.
- **Donor intake and performance:** inspect Bloodborne Enhanced for manual NG+ and rematches, not as automatic redistribution permission; inspect existing bbhost boss-rush and BBSC/BBport event, UI, input and render patches. Use Demon's Souls and other FromSoftware titles/mods as UX references, not copied assets. Compare exact upstream commits and mod implementations before writing new features. Profile on older and newer supported hardware; preserve functionality, improve or hold frame-time tails and CPU/RAM/VRAM, and do not promote a change on synthetic evidence alone.
