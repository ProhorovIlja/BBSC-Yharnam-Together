# Seamless Hunt Ultimate — playable track contract

Scope decision, 2026-11-15. This is a release and integration contract, not an implementation, deployment or claim of completed testing.

## Fixed decisions

- Extend the current Yharnam Together + bbport client, launcher and server. Retain the existing seamlesshunt.com service, player entry point and backend continuity. Server improvements are in-place upgrades after compatibility and rollback validation, not a move to another community's service. No production changes in this branch.
- The EBOOT-free runtime is paused for this track. Do not block playable improvements on it. Do not describe the current runtime as EBOOT-free.
- Preserve functions and existing settings when simplifying or replacing code. A rewrite must demonstrate correctness and a measurable resource or usability win on the same workload. Compare against a pinned upstream build and record both regressions and wins.
- Keep existing issues and Drive handoffs as evidence and backlog; this document is a routing index, not a replacement. New work records owner, branch, pinned SHA, donor/licence, test scope, and release status. Keep raw chats, saves, game files and credentials private.

## Website data path

Client observations and server-authoritative facts have separate provenance. Prefer facts already accepted by the server for counts, achievements and competitive records. Unknown, stale or unsupported is distinct from zero. Deduplicate by authoritative event identity; restoration, retry, reconnect and boss rematch must not count as new campaign wins. Anonymous aggregates by default; named profiles or public activity require sharing controls. No raw packets, chat, saves, credentials or IP addresses in public telemetry.

Use a bounded asynchronous queue and an aggregated read model; a slow database or website must not stall matchmaking or game traffic. Define freshness, duplicate behavior, retention, queue-full behavior and version compatibility before rollout. Public website requests should not query hot game state directly. Proposed additions require comparison with existing website feeds before implementing a second collector. 3D map is not a prerequisite for statistics or location lists.

## Co-op parity, communications and optional gameplay

Use the [cross-chat requirements ledger](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/blob/experiment/ultimate-batch-46-cross-chat-ledger-and-roster-dedup-20261110/docs/ULTIMATE_CROSS_CHAT_REQUIREMENTS_MASTER.md) as the historical index, this contract for current scope, and DEVELOPMENT-STATE.md on the active implementation branch for the exact SHA and evidence. A saved handoff is not live visibility into Work. Do not reopen or duplicate a task without checking its branch and issue first.

- **Seamless co-op:** benchmark the observable flow of Yui's Elden Ring and Nightreign mods, not their binaries or Steam backend. Bloodborne gates: party persists across lamps, zone/Dream/Chalice transitions, boss victories, player deaths and full wipes; correct spectator/respawn transitions; reconnect, host departure and safe exit; eligible earned rewards and optional additive Shared Progress without overwriting personal flags. Verify solo, host and guests with different progress in 2/3/5-player tests, base and DLC. Nightreign is a party UX reference, not proof of a campaign progression solution. See #22, #35, #162, #177 and #119.
- **Voice (#96):** independent opt-in proximity and team voice; distance and map scoping; mute/block, volume, PTT and microphone controls. No cross-map, hidden hostile or unrelated-session disclosure. Separate bounded realtime transport with authenticated scope and relay fallback; no recording by default and no blocking world updates on audio. No Dream For The Hunter publicly reports a voice implementation; its published local server repo is not proof that the audio client or a reusable voice transport is present. Inspect the client, license and protocol before adoption.
- **Text (#95, #103; drafts #98 and #102):** independently enabled team/session and global server channels. Team membership is checked server-side; global requires explicit scope, mute/block, spam controls and no private-session metadata. Direct messages are a separate scoped feature, not a prerequisite. Keep boss/system notices independently configurable. Team source exists in drafts; global and playable release are not verified.
- **Quit to Desktop (#78):** visible separate action in the original title/main menu, not just L3+R3, the overlay, System or Leave Team. Reuse a verified graceful exit path where applicable. Keyboard/controller, localization and tests for pending save, active session and launcher process cleanup; do not substitute force termination or shut down the persistent service.
- **Optional NPC relationships and new gameplay:** reuse the user's installed characters, animations, maps, bosses and item pool, plus new dialogue/windows where supported. Romance is an optional gameplay proposal: explore female-player/female-NPC and broader eligible combinations; exact routes, eligibility and rewards are not yet decided. Prototype one isolated per-character route with a fitting existing item, granted once, with no vanilla quest flag overwrite, host-to-guest import, or public activity leak. Validate saves, NG+, reconnect and disabling the module before expanding. No proprietary assets bundled.
- **External references:** Yui's mod pages are behavior/UX benchmarks; do not redistribute their files without permission. Hunter's Dream and No Dream For The Hunter are feature and protocol research sources, not service replacements. Inspect actual code before a candidate becomes an import. Maintain the distinct source, test, in-game and deployed statuses.
