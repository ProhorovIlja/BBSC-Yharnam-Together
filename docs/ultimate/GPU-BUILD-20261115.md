# Linux GPU compilation checkpoint

Date: 2026-11-15. This is compilation/link and CPU-test evidence for the
current integration branch, not a playable no-eboot native release.

## Changes

- Declare/link Abseil's `flat_hash_map` and `flat_hash_set` CMake targets. The
  texture cache already used them, but the standalone GPU build omitted them.
- Add optional `BB_USE_BUNDLED_BOOST=ON`, using the repository's actual
  `Boost::headers` target and its nested includes. System Boost stays the default.
- Pin GPU-specific Vulkan-Headers v1.4.347 at
  `387259ecf4b0fe0cfac161b1d0b0a74e42796710`. The existing FSR 4.1.1 feature chain
  needs C/Hpp declarations absent from the emulator's independent 1.4.330 pin.
  Require suitable headers at configure time; keep the FSR path and emulator pin.
- Add [the dependency helper](../../bbport/tools/build-pinned-gpu-deps.sh) and
  [Linux build instructions](../../bbport/docs/BUILD-LINUX.md). Install PIC
  dependencies, including Zycore's config for Zydis. Document Abseil on Windows.
- Bound `sceNpIntIsValidOnlineId`'s `strnlen` to its 16-byte data array. Its
  separate terminator is already checked; full-length valid IDs remain accepted.
- Repair existing test fixtures: use the loader's non-PIE/40-bit heap policy in
  the glibc runtime test, and exercise delayed touchpad gestures and overlay
  release behavior with a controlled monotonic clock instead of obsolete raw
  finger/click expectations. Production touchpad behavior is unchanged.

| Loader `--vulkan-only` | Instance creation returns -9; graphics execution not validated |

Host: Debian 13 x86-64, GCC 14.2.0, CMake 4.4.5. A user-writable SDK was built
from signed Debian package metadata plus pinned source dependencies. No system
package installation was required. Raw source pins, package hashes, compiler
logs and failed attempts are retained with the owner's private validation files.
Initial CPU-test failures were inspected rather than hidden: the runtime fixture
omitted the loader's allocation policy, and the pad test predated the map/ping
gesture contract. The updated tests preserve 40-bit assertions and verify the
new tap timing, side, touch identity and overlay release behavior.

LTO/PGO are off for this validation. glslang's optional optimizer/HLSL frontend
are off; current GLSL host shaders still compile normally. LSan cannot operate
under this environment's ptrace, so leak detection was disabled for the small
ASan/UBSan online-ID harness. This is not sanitizer coverage of the whole GPU
library or a leak-freedom claim. Build warnings outside the corrected bounds
issue remain to be triaged. Staged runtime search paths are not portable packaging.

## Upstream review and remaining work

Inspected deadinside28/bloodborne_pc's GPU CMake blob
`9e7cb5d6198b07e9e6de37d1af16db6e3df59914`: it retains system Boost and has
additional PGO/profile-path and renderer changes. These were not wholesale
imported. shadPS4's np_common.cpp blob
`eed77a992018a32486be77fb1098be25e4f0de51` still has the same length+1 scan;
the local correction is not an upstream fix claimed as integrated.

Next: actual device/render tests, full native/runtime interface and retail
profile audit, asset loading and game-main progress. The native diagnostic
prefix remains 128. This checkpoint does not implement the independent 60 Hz
simulation, D3D12/Metal, DirectStorage, Windows/macOS full game builds, hybrid
multiplayer acceptance or no-eboot gameplay. No performance gains are claimed.
