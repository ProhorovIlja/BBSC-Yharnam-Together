# Locale-independent paths for the NGX bridge

Problem source: [Awakenchan/LanternEngine #104](https://github.com/Awakenchan/LanternEngine/pull/104),
head `49df4762e84a259c79ceff5d4cec6963b0e7f8a0`, inspected open/unmerged. The upstream report
describes Linux DLSS discovery failing when non-ASCII install paths pass through `wstring()` and
NGX's locale-dependent conversion. Its upstream game test is not gameplay evidence for this branch.

The current renderer also called `ngx.wstring()` and `data.wstring()` on Linux. Adapt the problem
at the existing bridge boundary: `BbNgxPaths::Paths` keeps Windows native UTF-16 paths, and on
POSIX gives NGX ASCII directory aliases when either native path contains non-ASCII bytes. The
aliases live in a unique `mkdtemp` directory (0700) under `/tmp`; they point at the original
runtime/data directories. Files are neither copied nor overwritten. Missing directories fail
before bridge configuration. The process locale is unchanged, including under `LANG=C`.

The renderer holds the aliases through NGX use and releases them after bridge shutdown. RAII
also cleans up construction failures. Symlink cleanup does not follow or delete original targets.
Abrupt process termination can leave a small private alias directory; normal shutdown cleans it.
The approach differs from the upstream decoder/copy/locale implementation; none of that code is
copied. The existing Windows native path behavior remains in use.

Tests use the production helper with real directories and file I/O under locale C: four
ASCII/Unicode runtime/data combinations (Cyrillic, CJK and emoji), reads of a fixture module,
writes visible in the original data directory, POSIX 0700 permissions, distinct simultaneous
alias directories, cleanup, original-file preservation and missing-path rejection. Linux logs
also diagnose both conversions: this local standard library accepts `path.wstring()`, while
NGX-style `wcsrtombs` of Unicode fails under C. Conversion of the production ASCII aliases
succeeds under that same locale. CI runs this portable
helper on Windows/Linux/macOS; macOS helper coverage does not establish macOS DLSS support.

The full renderer/bridge is not built locally: Vulkan/NGX SDK prerequisites are unavailable.
No NVIDIA GPU, NGX module loading, DLSS feature availability, frames or gameplay are validated.
The filesystem/helper test does not certify all proprietary-runtime internals, unexpected host
termination cleanup, Windows long-path discovery or concurrent shutdown/reinitialization.
