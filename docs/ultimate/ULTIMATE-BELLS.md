# Ultimate: bell-driven online

Status: acceptance policy only; no client hooks, matchmaking deployment, or runtime replacement. This supersedes the no-bells UI decision, not the Yharnam Together session backend.

- Expose Host, Join, Invasion and Duel bells from character creation (including existing characters via idempotent unlock), with no Insight cost or story unlock. Start advertising/searching immediately once authenticated; show a reason if a transition is currently unsafe. No automatic PvP consent from owning a bell. Silencing Blank cancels the matching intent; explicit confirmation distinguishes cancellation from closing a live room.
- Use the in-game Network password and Local/Worldwide setting. No duplicate setting in the launcher. Both public players need an empty password; password co-op matches only the same password and bypasses the level band, not platform/protocol compatibility, region policy, slots, or safe travel. Server derives scoped private buckets from authenticated requests; do not store, echo, log or publish raw passwords or unsalted password hashes. Do not reinterpret Local as LAN; keep it a region filter, including when the other side chooses Worldwide. Map-independent discovery is not unsafe travel: reserve on the server, revalidate before sending a player to a known compatible destination. Do not widen public bands or cross Local boundaries silently.
- Public level bands in the fixture are provisional and distinct by mode. Level zero is not eligible for public matches. Invasions use the existing opt-in, gameplay/cooldown and reservation checks in addition to filtering; do not treat a shared password as permission to invade. Initially keep private rooms out of involuntary invasion search. Maintain the five total / up to two hostile design gates, with actual admission under the existing server authority. No separate bell transport or second room registry.
- Duel Bell proposes an explicit 1v1, 2v2 or 3v2 inside the session. 3v2 is opt-in with all five non-hostile players; do not silently switch formats after a decline or timeout. Only consenting non-hostile players count toward teams, never invaders or spectators. Host approval plus explicit per-player consent; unique identities and teams frozen by the server. Revalidate arena, occupancy, map and combat state; do not start during a boss or an active/pending invasion. No duel damage to nonparticipants, progress or save writes. End on disconnect/invalidated match; prove cleanup before expanding formats. Relay initially.
- Downscale substantially over-levelled password guests in a temporary session layer; don't rewrite level, equipment, inventory or saves. Start with tuning HP, outgoing damage and relevant defence, benchmark different builds and weapons, and verify restoration on quit, disconnect, host travel and rejoin. Keep duel balance separate. Prefer reuse of measured Bloodborne behaviour if verified in 1.09; DS3/Elden Ring are references, not data shipped with Ultimate.
- Retail references: PlayStation Blog patch 1.04 confirms password matching irrespective of level, and its retail summoning guide requires the same area. Community patch 1.05 notes describe scaling high-difference password guests. Cross-map search and immediate free bells are Ultimate changes, not claims about retail.
- Wire one shared action layer into the current and recompiled runtimes. Audit actual item-use hooks and Network fields per supported 1.09 build. Native no-PS4-module launch remains a parallel gate; do not wait for it to test the shared policy.

The fixture does not implement authenticated identities, token derivation, queue ranking, safe arrivals, atomically held seats, actual duel teams, combat routing, or downscaling. Those must pass real staging tests before promotion.
