# Whole-function AOT boundary research

The previous single-instruction differential probe did not test generated function
tables, call dispatch or guest stack returns. `recompiler_functions_probe.py` adds
those checks against the same clean, pinned external recompiler and bbcpu API4.
It creates a disposable ELF containing nine original test functions, invokes the
real full-function generator, then compiles its table/shard with an independent C
test host. There are no commercial game bytes in this fixture.

## What actually passed locally

Seven supported functions each run with 1,000 deterministic input states and
generated direct-call slots both disabled and enabled: 14,000 cases. Integer
inputs include wrapping values. The two negative functions are never admitted to
the normal dispatch allowlist.

| Boundary | Checked behavior |
|---|---|
| Direct CALL and RET | Stack return and continuation survive both dispatch modes |
| Indirect CALL | Exact target allowlist; dispatch reaches the generated callee |
| Tail JMP | Original return slot consumed once; direct and callback paths agree |
| Host callback | Six guest integer registers and two stack arguments retain their positions |
| Host-to-generated reentry | Nested leaf returns to the original callback continuation |
| FS:[0] and GS:[0x40] | Generated code reads the CPU context's TCB, including a non-RAX destination |
| Preserved registers | RBX except the intentional TCB write, RBP and R12..R15 unchanged |
| Unsupported paths | FS:[0x40] and SYSCALL reach the terminal step hook at their exact fixture RIP |
| Unknown target | Rejects a hole in the image range, rather than treating it as executable |

The success batch records 5,000 call callbacks, 1,000 tail callbacks, 2,000 host
callbacks/reentries, and no interpreter-step or bail calls. Generated source
contains generic dispatch/bail epilogues; a source-text substring is not execution
coverage. The test host makes any reached step/bail terminal. Three additional
processes verify the expected rejection codes for unknown/unsupported paths.

The same suite passes with AddressSanitizer and UndefinedBehaviorSanitizer on the
test host **and generated C**. Leak checking is disabled: this environment's
ptrace-backed process execution prevents LeakSanitizer from running. Generated
unused-label/variable warnings remain visible; this is not a warning-free donor.

CI now runs the whole-function probe after the existing 20,000-state differential
instruction test. The standalone command requires the already built pinned tools:

```sh
python tools/ultimate/recompiler_functions_probe.py \
  --recompiler /path/to/bloodborne-recomp --bbcpu /path/to/bbcpu \
  --deps /path/to/isolated-decoder-prefix --output /path/to/fresh-results
```

`--sanitize` instruments both C inputs. Evidence includes fixture, generated-source,
generator-binary and test-host identities, source pins and explicit untested scope.

## Upstream work used as a reference

The actual external source pins remain:

* bloodborne-native/bloodborne-recomp `c60ccf8be752b8690f2813505c4daf9eafdb136b`.
* bloodborne-native/bbcpu `3f9b6c1a11d5a443ee2e556a0d1f3aec4a73f0ca`.

Their GPL-2.0-or-later interfaces/tools and existing bbport/shadPS4 credits remain
external; no donor runtime or generated game code is vendored here.

The synthetic ELF and TCB-counterexample approach was informed by
[V401 / PR131](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/131),
head `f151b8f79ee6bbaee81797efcc8b146845e2db09`, particularly
`generate_tcb_probe_v401.py`, `generate_verified_imports_v395.py` and the bounded
TCB-hash header. That branch uses an older generator pin and remains draft work;
we wrote an independent fixture/host against our API4 pins. No V401 source is
copied. Its distinction between normalized decoded hashes and raw byte hashes is
relevant to future function admission, but our probe does not implement a general
runtime hash verifier. The V392 entry-lease audit, PR122 head
`e43c5c0220460f49891c9c25acc0b7d9481e45e9`, is a further reference for nested
entry/memory ownership, not a lease implementation imported by this PR.

## What remains before production use

This test host models guest state in `BbCpu`; it is not a Windows SysV-to-Win64
machine-code bridge. Native Windows/macOS/ARM64 execution, threading/lease safety,
nonlocal exits, exceptions, dynamic patch exclusions, general decoded hashes,
untrusted memory protection, vectors/floating point, and retail function replays
remain separate work. No production AOT dispatcher, game-main execution, renderer,
assets, save loading or playable no-eboot profile is enabled. The independent
[native140 owner diagnostic](NATIVE-STARTUP-140-EVIDENCE.md) proves only its stated
startup prefix. Neither test upgrades the other's scope.
