## Required test baseline and quality bars

1. **Baseline:** clean Bloodborne 1.09 with matched game region (nine CUSA variants in #84), DLC, build commit, GPU driver, machine CPU/RAM/VRAM, resolution, upscaler/FG, render patch, savedata *copy*, mods hash. Do not bundle proprietary game content with public code.
2. **Correctness gates:** 10 save-load-rejoin loops, 10 launch/exit loops; 20–60 min solo/co-op stability and longer 1–2-hour sessions. Zero memory leaks proven only from sustained stabilized working-set/VRAM slopes, not a single reading. GPU errors/driver resets, visible floor/mesh correctness and collision tracked independently.
3. **Performance:** capture GPU and CPU times separately; frametime median/p95/p99, 0.1% low and long spikes, shader build timings, PCIe readbacks/s, VRAM eviction and texture fallback, server CPU time/room, RSS and net packets/s, input-to-photon latency (Reflex markers when available). Define a threshold after real baseline; don't fabricate FPS, RTT or improvement percentages.
4. **Settings:** prefer tested, low-surprise defaults. Advanced risky optimization toggle includes availability/driver requirement, warning and rollback. One UI for launcher/client/server, with presets Smooth/Balanced/Quality/Low-VRAM/Low-Latency that map to *real* supported codepaths, not UI-only labels. Do not simultaneously force incompatible frame pacing limiters or overlays.
5. **Rollout:** all changes as Draft stacked PRs, targeted native and Windows CI, peer review, gameplay rig, profiling with reproducible machine and release-rollback manifest; no early mass rebuilds or unsafe blanket merges.
6. **Privacy & uptime:** no private Discord screenshots/game saves/credentials published; no production Fornex changes or process restarts without explicit safe deployment gate. Keep source-derived cases separate from unverified user reports and vendor marketing.
