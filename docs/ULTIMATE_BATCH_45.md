# Ultimate B45: independent social/map controls, real team levels and deterministic 18+ build labels

2026-11-10. Stacked on [B44 PR #102](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/pull/102). User requirements are durably tracked in [Issue #103](https://github.com/ProhorovIlja/BBSC-Yharnam-Together/issues/103). No Fornex/game assets/saves touched.

## Actually changed in production source

1. **Independent persisted local options**: `bbport/gpu/shim/bbport_settings.{h,cpp}` reads/writes `bbport.ini` boolean keys: `social_chat` (true), `social_boss_events` (true), `map_teammates` (true), `map_teammate_names` (true), `roster_levels` (false), `roster_latency` (false), `roster_builds` (false), `share_build_stats` (false). The in-game Insert > Display settings screen exposes these switches and indicates which have no live data yet. These do NOT change server team/invasion settings.
2. **Map markers and captions**: if `map_teammates=0`, teammate markers and captions on the in-game map are omitted, while the local player's arrow, lamps, geometry and travel functions remain. `map_teammate_names=0` hides teammate names independently of showing marker portraits. `roster_levels` adds real level labels to teammate map markers when known.
3. **Chat vs hunt events**: `Team::PollChatEvents` consumes and discards disabled categories. Turning off text chat clears its own old displayed text and the unsent draft and disables Send/Enter; team boss-victory notices remain a separate opt-in. Turning off boss events clears previously shown system events and drops new ones. When chat is off but boss feed enabled, the team-screen button becomes `Hunt feed`; if both disabled, it cannot open. New local settings are applied when the team screen updates and are not yet an authenticated server-side no-delivery subscription.
4. **Real teammate level, never guessed**: the existing authenticated `VitalsBoard::Member.vitals.level` (which is already used for invader level-band matchmaking) is copied into `PanelMember.level`, `bbcoop_map_member.level`, and teammates' `bbcoop_lobby_entry.level`. Non-team accounts, absent session data, and old clients remain unknown (0). Player browser respects `roster_levels`, displays a visible `Lv. —` when unknown. No inference from roster ordering or network count.
5. **16 distinct four-stat build archetypes**: `bbport/gpu/bbcoop/build_archetype.h` classifies valid Strength, Skill, Bloodtinge, Arcane values with an inclusive threshold `>= 18` for each. Bitmask 0..15 maps to 16 unique English/Russian labels, including mono, every 2-way and 3-way combination, `Quality` for STR+SKL, `Omnibuild` for all four and `Unfocused` if all below 18; out-of-range/unavailable stats return Unknown rather than a false label. Pure C++20 tests check 17/18, every bitmask, localization uniqueness, invalid data. **This is a tested classifier, not a connected network profile service**. The current roster shows `Build: —` when enabled until a consented, verified per-account profile data channel is implemented. `share_build_stats` is a saved opt-in placeholder only: it does NOT transmit user stats yet.
6. **Optional ping**: `roster_latency` renders `Ping: —` until an actual fresh RTT sample with a declared origin is available. Co-op world replay delay, transport RTT to the server, TCP vs UDP and peer-to-peer RTT must be distinguished. The option is not a claim to currently measure per-hunter latency.
7. **PvP Quick Match naming**: existing server `InvadeRequest` matchmaking (opt-in, one at a time, started team, level band, cooldown, timeout, host/team choice) is now labelled `Quick PvP invasion` in the team menu rather than generic `Invade a hunt`, with a `Cancel PvP search` action while searching. This is existing functionality, not a new PvP matchmaking algorithm. Manual targeting and browser-filtered invasion are still separate backlog.

## Research and source-provenance

- Yharnam Together upstream v1.4.0 released 2026-11-06 includes a **teammate BLUE phantom glow** visual toggle, not a verified **invader RED** glow toggle. Current code `bbport/launcher/bbport_coop.py` has `hide_glow` for blue teammates and launcher `bbport_launcher_win.py` supplies its UI. An invader-specific local red aura toggle needs its own rendering/game patch investigation, so no misleading red switch is presented as working yet.

Existing current `docs/INVASIONS.md` describes server matchmaking and game implementation caveats; candidate upgrades should reconcile and test instead of blindly copying.
- GitHub external candidates include independently authored `droogie/bbhost` PR #217 multiplayer handshake/lifecycle, #141 command-processor CPU-side optimization, #231 controller glyphs; `Supermedo/bloodborne_pc`, `deadinside28/bloodborne_pc`, `mark3317/bbgl`, `mark3317/bbsc-gl`, shadPS4 and other related forks. No external change was merged blindly into B45; licenses, revisions and tests require separate audit. It is not feasible to claim exhaustive indexing of every GitHub repository or branch.

## Safety

No deployment, no persistence of private chat messages, no game binaries, no private game content in GitHub. `bbport.ini` is a local preferences file. If privacy is the player's goal rather than only UI decluttering, server-side profile opt-out and no-delivery subscription remain necessary.
